# Курсик — мини-приложение MAX

React + TypeScript + Vite. Макеты: [Figma, секция «Аппка max»](https://www.figma.com/design/z1DfrJ2RqWWdjgcii6ZY2p/Untitled?node-id=297-1970).

```sh
cd frontend
npm ci
npm run dev
npm run build
npm test
```

Откройте http://127.0.0.1:5173. Node.js 22.12+ (тесты без компиляции — Node.js 22.18+).

## Что уже работает

- Приветствие, оригинальные иллюстрации и SVG из Figma, локальный Inter.
- Выбор 1–3 направлений; специализации; языки; цели; обучение; формат и города.
- Города России: локальный справочник, подсказки с исправлением опечаток по подтверждению пользователя, выбор региона для одноимённых городов, проверка на фронтенде и backend. Источник и лицензия — `../backend/internal/geography/README.md`.
- Вопросы и шкала из API, возврат к ответам, проверка перед завершением.
- Последовательное сохранение полного черновика с ревизией; повтор завершения с тем же ключом при неизвестном исходе.
- Восстановление черновика; при конфликте предлагается явно загрузить серверную версию. Автоматического слияния полей пока нет.
- «Твой курс»: направления переключаются стрелками, качественный результат без числовых оценок и списка ответов; курсы загружаются отдельно.
- Каталог с категориями и независимыми фильтрами направления/формата; избранное с иконкой справа сверху; закрытые и отсутствующие карточки.
- Профиль и отдельный экран данных/приватности; подтверждения выхода и удаления через нативный dialog с двумя полноценными кнопками.
- Повторный тест очищает оценки, сохраняя предпочтения и прежний результат до завершения. Существующий черновик продолжается, а не затирается.
- Галочки B2 и три позы/положения Курсика при смене вопроса, с поддержкой reduced motion.

## API и вход

Используется исходный клиент `../api/client/client.ts`, без копирования контракта.
Dev proxy `/api` → `http://127.0.0.1:18080`. Production — тот же origin.
[Запуск backend](../docs/frontend.md). Bearer хранится только в памяти.
[Официальный MAX Bridge](https://dev.max.ru/docs/webapps/bridge) загружается при входе; передаётся исходный `window.WebApp.initData`.

Для локального backend с синтетическим пользователем сгенерируйте `init_data` по инструкции backend, откройте экран входа и «Локальный вход для разработки». Вставьте только значение строки. Оно не сохраняется в localStorage и очищается после входа. Не используйте реальные токены бота.

## Демо для просмотра

На dev-сервере под приветствием есть «Открыть демо без MAX». Это изолированный клиент в памяти без сетевых запросов к backend. Вопросы берутся из локального банка; порядок и подсчёт здесь демонстрационные. Карточки явно помечены как демонстрационные. Перезагрузка сбрасывает состояние. Код демо и элементы локального входа исключаются из production-сборки.

## Проверка и границы первой версии

Проверены TypeScript, production build, unit-тесты зависимых вопросов и очистки ответов; браузерный демосценарий от приветствия до результатов, избранное и фильтры, ширины 390 и 320, короткий экран 568 px. Нет горизонтального скролла и отсутствующих изображений в проверенных состояниях.

В этой итерации не проверены реальная авторизация в MAX и работа с развёрнутым backend. Следующий этап — интеграционные проверки сетевых ошибок/конфликтов и полный проход по реестру служебных состояний. Изменение набора направлений обновляет preview и удаляет неактуальные ответы; отдельное подтверждение изменения набора вопросов ещё не реализовано. Для политики приватности ещё нужен утверждённый документ/URL. Автоматическое слияние конфликтов и отмена черновика через `discardDraft()` пока не включены в UI.

Основной `docker compose up --build -d` из корня репозитория собирает frontend внутри Docker и раздаёт его через общий Caddy на `http://127.0.0.1:18080`. На хосте Node.js для этого не нужен. Production-сборка не включает демо и локальный вход: для них используйте `npm run dev`. Необязательный `make up-frontend` подключает заранее собранный на хосте `frontend/dist/`. Секретов и env-файлов backend во фронтенде нет.
